02｜用户反馈的问题

先拿三项信息

账号和 App 版本截图必须有，问题描述和材料一并带上。

用户是谁｜必须账号

先确认是哪一个用户。

例：user_1234（虚构账号）

App是否正常｜必须App版本截图

同时确认用户端状态。

例：v5.12.0＋版本页截图

用户发生了什么描述＋材料

用户问题描述，以及相关截图或录屏。

例：点击提交一直转圈，附10秒录屏

对客户这样说“我们会把信息反馈给研发老师，解决后再通知您。”

不是马上通报，而是让客户知道：问题有人跟，解决有通知。

拿到后：到飞书向 Agent 说明，留下 Ticket 跟进。
运营老师负责问清信息并传递，不让研发从头追问03 / 08
03｜Feature建议与体验优化

两项可选，一项说清

重点不是用户出了问题，而是用户希望什么变得更好。

用户是谁｜可选账号

需要进一步核实时再使用。

例：提供账号，便于后续回访

App是否正常｜可选App版本截图

有体验差异时提供更有帮助。

例：v5.12.0＋版本页截图

用户希望改进什么建议＋材料

改进描述，以及相关截图或录屏。

例：希望报表按周导出，附当前页面截图

对客户这样说“谢谢您的建议，我们会反馈给产研同学。”

表达感谢，但不承诺采纳，也不随口承诺排期。

拿到后：到飞书向 Agent 说明，留下 Ticket 跟进。
建议被认真听见，比当场给一个不确定的时间更重要04 / 08
04｜紧急异常

这四种情况，单独处理

先安抚客户、拿到用户信息，再马上升级。

用户账号消失例：昨天能登录，今天查无账号
用户会员状态异常例：刚续费，仍显示会员过期
大范围接口异常例：多位用户同时无法加载
任何资金相关问题例：扣款成功，订单却未生效
发到微信群，并直接电话拉起研发老师。
微信负责预警，电话负责拉起；不要继续在群里打字排队。
例子为虚构场景；紧急问题不走普通 Ticket 排队05 / 08

一般账号问题，去问运营 Agent

普通账号咨询和处理，不占研发紧急通道。

运营 Agent 直接问，直接跟

例：用户想修改绑定手机号

两种情况别走这里账号消失

一般账号问题找运营，紧急账号异常马上拉起研发。
同样是账号问题，也要先看是否属于紧急异常06 / 08
